--------------------------------------------------------------------------------
1. WHAT THIS THING IS
--------------------------------------------------------------------------------
"NOVA POC" / "sallaapam": an Amazon-Nova-flavoured chat frontend + a FastAPI
backend that normalises 12 OpenAI-compatible providers into one OpenAI-style
/chat/completions interface. The webapp is a Vite+React (jsx) SPA; the server
is pure FastAPI + httpx, deps are only fastapi/uvicorn/httpx/multipart/evtx
(no torch/numpy). SQLite (nova_history.db) stores conversations + a token-usage
ledger. There is a Settings panel with per-provider model pick, Reasoning &
Agent toggles, Image generation, a Malayalam language preset, and a "Security
Mode (NovaSec)" cyber-expert preset.

Two modes of UI behaviour:
- Normal chat            -> forwards to the selected cloud provider verbatim.
- Conversation agent      -> provider + model, optional image input, tool round
                              budget (max_tool_rounds), reasoning_effort.
- Malayalam mode          -> forces provider=gemini, model=auto + a MALAYALAM
                              system prompt prepended to messages.
- Security Mode (NovaSec) -> swaps in a cybersecurity-expert system prompt + a
                              `<Shield>` icon + an on-screen "NovaSec active"
                              chip. No backend changes — purely a prompt/icon.

6. HOW IT'S HOSTED ON THE PHONE (START / RESTART)
--------------------------------------------------------------------------------
Start (the actual command the phone runs):
  set -a; . "$HOME/NOVA_Project/.env"; set +a
  export APP_HOST=0.0.0.0 APP_PORT=8000 NOVA_HISTORY_DB="$HOME/NOVA_Project/nova_history.db"
  nohup "$HOME/NOVA_Project/.venv/bin/python" -m uvicorn backend:app \
        --host 0.0.0.0 --port 8000 > "$HOME/NOVA_Project/nova-app.log" 2>&1 &

Restart (backend.py changed):
  pkill -f 'uvicorn backend:app'   ; sleep 1
  then re-run the Start block above.
  (pid was 18044 at handover; the tunnel stays up — do NOT restart it.)

Restart (frontend-only changed, e.g. static/App.jsx):
  NONE needed. FastAPI serves /static from disk per-request via StaticFiles.
  A `git pull` (or copy of new static/) is enough — no uvicorn restart.

Keep-alive (Termux): termux-wake-lock  (script runs `termux-wake-lock`).
Auto-start on boot: install "Termux:Boot" from F-Droid and add a script that runs
the Start block (see end of termux-deploy.sh).

Health gate used by the deploy scripts:
  curl -sf http://localhost:8000/api/health   (loop ~40x2s / 50x2s)

--------------------------------------------------------------------------------
Framework: FastAPI. Serves static SPA from /static via app.mount('/', StaticFiles).
Routes (@app):

  GET  /api/ollama/status                (959)

  POST /api/ollama/unload                (982)

  GET  /api/conversations/{cid}          (1400) get
  POST /api/conversations/{cid}/clear    (1425) clear
  POST /api/conversations/{cid}/delete   (1408 / 1418)
  GET  /api/usage                        (1443) returns {total,by_model,by_provider,by_day,first_seen,recent}
  POST /api/chat                         (1468) main; returns messages + title
  POST /api/images                       (1746) image generation
  POST /api/analyze                      (1788) file/usage analysis
  GET  /  /mobile  /usage                (1896/1901/1907) StaticFiles

DB helpers (sqlite3, nova_history.db):
  db_usage_summary(provider, model, days)   (1283) -> totals + by_model/provider/by_day
  db_usage_recent(limit)                    (1364) -> cols: provider,model,role,
                                   prompt_tokens,completion_tokens,total_tokens,
                                   reasoning_tokens,created_at
  db_get_conversation_title(cid)            (1186)  [added during the naming fix]
  db_save_message(...)                    (1259-1267) auto-titles new convos
  db_update_conversation_title(...)

ChatRequest(BaseModel) @634 (OpenAI-compatible):
  messages: List[Dict[str,Any]]
  model: str = ""
  agent: bool = False
  provider: str = ""   # empty -> DEFAULT_PROVIDER
  (+ conversation_id, api_key, max_tool_rounds, image, reasoning_effort etc.)
backend.py forwards provider messages VERBATIM to the provider; the system-prompt
presets (Malayalam / NovaSec) are injected by the FRONTEND (App.jsx send()) and
are NOT applied server-side.

Provider routing / failover implemented in backend (per provider):
  - Gemini 403 -> retry with GEMINI_API_KEY_BACKUP.
  - IFM/K2 retry on transient 400 "missing thinking field" (commit 155ac4b fix).
  - Reka uses the X-Api-Key header; NVIDIA uses Bearer nvapi- key.

Usage DB reality (handover sample, live on phone):

- DO NOT try to run an uncensored LLM locally on this phone: SM8350-class SoC,
  no GPU, no ollama/llama.cpp installed, ~392 MB free RAM headroom; even the
  smallest uncensored GGUF (~2.7B) + uvicorn exceeds available memory. The only
  "local/uncensored" provider wired up is Ollama (localhost:11434) — it is NOT
  installed on the phone. All other providers are cloud and apply their own
  safety filters regardless of system prompt (so NovaSec is a bounded cyber-
  expert persona, not an uncensor).
- DO NOT defeat cloud-provider safety filters via prompt — they fire at the API
  layer, not the model layer.
- DO NOT restart the Cloudflare named tunnel unless you must; a quick tunnel
  restart rotates the public URL.
- DO NOT `cat .env` in terminals/logs. The backup .env is secret; the on-disk
  .env on the phone is gitignored.
- .venv in the backup is a tarball (symlinks); it restores cleanly on the phone
  (Linux FS) but not as a live tree on this exFAT SSD.
- backend.py changes => restart uvicorn. static/frontend changes => no restart.
